The Proving Ground Terminal. In Figma.

A production-grade Figma Design Ops handoff specification for the V-100 Proving Ground Terminal — the air-gapped Xterm.js + WebContainer execution surface where Hard-Gate verification happens. Frame architecture, auto-layout properties, component variants, prototype triggers, dev-handoff tokens, accessibility notes. Every constraint defined. Every variant enumerated. Ready to drop into a Figma library.

§01Overview & Strategy

What we're building. Why it's complicated.

The Proving Ground Terminal is the platform's most consequential surface. The user works in a real Xterm.js shell against a WebContainer sandbox while the four-agent council watches, the Adversary Logic Engine injects chaos, and the Triple-Threat Scoring Engine recomputes AICI / AIOI / AIBS in real time. The Figma source of truth must reflect that complexity without losing the Digital Curator editorial restraint.

CONTEXT · 02 The strategic design tension

Every other Tenured AI surface lives on warm #FCF9F5 paper. This one breaks the rule — the terminal must be dark, dense, and instrumented like a financial trading workstation. The challenge is making a dark interface that still reads as Digital Curator: editorial, sovereign, architectural — not gaming-aesthetic, not cyberpunk, not crypto-loud.

The Figma library must produce a terminal that feels like the interior of a sovereign data center, c. 1969, retrofitted with modern instrumentation. Amber CRT glow on telemetry. Warm teak undertones on the chrome. Brass service accents only where they earn the visual weight. No grid-of-pixel-skull aesthetics. No matrix-green-on-black. No glitch effects unless the Chaos Engine is actively firing.

DESIGN ETHOS — THIS SURFACE

"Editorial restraint, even in the dark."

Every decision in this spec asks one question: would a Bloomberg terminal designer or a NASA mission-control engineer recognize this as a serious instrument? If the answer is yes, the design is on. If the answer is "looks like a coding bootcamp dashboard," strip it back.

§04Grid & Constraints

The platform's other surfaces (Passport, Forge, Tenured Agent) support mobile; this one does not.

GRID · 04 The No-Line Rule — implementation in Figma

The Digital Curator system's No-Line Rule applies even in dark mode. Never use solid 1px borders for sectioning, containment, or framing. Boundaries are defined exclusively through:

  • Tonal shifts. Each elevation tier uses a different background fill (bg/base → bg/panel → bg/elevated). The shift between layers creates the visual boundary.
  • Generous gaps. Auto-layout gaps of space/6 (24px) or larger define separation between major UI groupings without requiring lines.
  • Effect-based depth. Shadows (elevation/sm, elevation/md) create lift; lift creates implicit boundary.
  • Ghost-border exception. The only permitted use of a 1px stroke is on input focus states: outline-variant at 15% opacity, never higher. In Figma: this is an interactive state on the input component, not a default stroke.

Figma library check: Periodically audit components for hidden stroke values. The library lints for any stroke that isn't on a documented focus-state variant. Strokes on default components fail the audit.

A11Y · 04 The No-Line Rule and screen reader accessibility

The No-Line Rule (defining boundaries via tonal shift and white-space instead of borders) is a visual rule. It does not affect screen reader users at all — they consume the document structure through ARIA roles, landmarks, and heading levels, not visual borders. Every component carries explicit semantic structure so screen reader navigation works regardless of whether sighted users see boundaries as lines or as tonal shifts.

Specifically: every major frame (terminal-main, telemetry-rail, council-strip, command-drawer) carries an explicit ARIA region with a descriptive aria-label. Screen readers announce these region boundaries clearly. Sighted users see them through tonal shift. The two systems are decoupled by design.

A11Y · 05 Motion sensitivity
  • prefers-reduced-motion: reduce · honored everywhere. Specifically:
  • chaos-banner pulse → static color (no animation)
  • session timer → updates without ease (instant value change)
  • Smart Animate flows → reduce to crossfade only (240ms ease, no element movement)
  • Sovereign gradient sweep on mint → static gradient (no sweep animation)
  • CRT glow effects → reduced opacity (5% instead of 20%), no pulse
