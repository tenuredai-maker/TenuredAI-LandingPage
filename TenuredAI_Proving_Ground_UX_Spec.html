PG v2 / F1Foundations · The Verification Crisis

Static assessments are dead. The LLM killed them.

PAT-001's market premise: a candidate can submit any coding challenge to GPT-4 or Claude and receive a complete, syntactically perfect solution in seconds. Multiple-choice tests, take-home assignments, even most "live" coding interviews are forensically empty — they certify access to an AI, not technical reasoning. The Proving Ground is engineered specifically to defeat this attack: an environment whose ground truth state is known only to its Adversary Logic Engine, where AI assistance is mathematically detectable in telemetry, and where the credential issued is anchored to a multi-agent consensus that no single-model gaming can satisfy.

PAT-001 §A
PRIOR ART FAILS

Static tests are gameable

HackerRank, LeetCode, coding interviews — all rely on the candidate's input being the only signal. The LLM has made that signal forensically empty.

PAT-001 §B
THE GAP

No portable Proof of Friction

No system generates a forensically verifiable time-series record of how the candidate engaged — only of what they submitted. Output telemetry can't distinguish human reasoning from AI mediation.

PAT-001 §C
THE PROVING GROUND

Environmental epistemic closure

An air-gapped containerized environment whose full state is known only to the Adversary Logic Engine — creating problems that require situationally-embedded human cognition.

Strategy · why this UX matters

The Proving Ground is the platform's most defensible patent claim and its hardest UX challenge: it must feel like a real engineering environment (so the engineer engages genuinely) while behaving like an instrumented adversary (so the council can grade authentically). Every screen in this spec walks that line. The patent-derived vocabulary (ALE, ALTFL, PoF, Command Authority, Consensus Certificate) appears in the UI itself — not buried in marketing copy — because the user's trust in the credential depends on seeing the rigor.

PG v2 / F2Foundations · Environmental Epistemic Closure (PAT-001 §C)

The LLM can't help if it can't see.

The patent's core defensive claim. An external LLM (ChatGPT, Claude, Copilot) operates only on the information the user pastes into its prompt. The Proving Ground's full mutated state — the active failure injections, the Bully Logic state machine's current position, the ALE's pending second-order injections — exists outside the user-accessible scope. A user can paste their terminal output into ChatGPT and ask for help, but the LLM will diagnose the visible symptom without awareness of the actual hostile environment behind it. This is mathematically guaranteed to produce wrong advice; the ALTFL telemetry then detects the user attempting it.

WHY IT HOLDS
  • · The ALE state is server-side, sealed, never serialized to the user's screen.
  • · Failure injections are covert — symptoms surface as the engineer normally expects them.
  • · The Bully Logic Persistence Loop re-injects through different symptom vectors, so any "pattern" the LLM learns becomes invalid one turn later.
  • · The Council Invigilator's ALTFL signature detector flags AI-typical keystroke bursts and inference latency.
WHAT THE LLM SEES IF QUERIED

"my gateway is returning 503, what do I do?"

→ but the ALE has rotated the auth keys, not the gateway

Designer's Note · the moat made interactive

Environmental Epistemic Closure is the platform's most defensible IP claim — and the user must feel it during the Gate. The terminal shows real errors with real symptoms, exactly the way an engineer would expect them in production. The fact that the engineer can't fix them by Googling, can't fix them with ChatGPT, can only fix them by genuinely understanding the system — that is the credential's value. The UX never advertises "LLM-resistant" as a feature on a marketing label; instead, every screen of the Gate makes it experientially obvious that no shortcut works here.

PG v2 / F3Foundations · The Adversary Logic Engine (PAT-001 SUMMARY)

The engine that mutates the environment.

The Adversary Logic Engine (ALE) is the Proving Ground's adversarial core — a server-side state machine that schedules and injects stochastic, context-aware failure events based on continuous assessment of the user's interaction. The ALE is what the user is actually fighting; the Chaos Agent of PAT-004 is the council member that dispatches the ALE's injections. The user never sees the ALE directly; they see only its consequences — gateway timeouts, dependency hallucinations, key rotations, [CHAOS] gaslighting lines.

FIRST-ORDER

Stochastic environmental failures

Network partition, dependency unavailable, config drift, key rotation. ALE selects by weighted draw from the active node's failure library.

SECOND-ORDER

Bully Logic re-injection

If the user's remediation pattern-matches a memorized solution, ALE re-injects in the same domain via a different symptom — requires genuine domain comprehension.

META

Gaslighting (PAT-001 +)

[CHAOS] lines that assert the user is misinterpreting the environment — testing conviction, not just remediation skill.

PG v2 / F4Foundations · Bully Logic Persistence Loop (PAT-001 FIG 3)

The state machine that punishes pattern-matching.

The Bully Logic Persistence Loop is PAT-001's defense against memorized-solution gaming. After every failure injection, the ALE assesses whether the user's remediation reflects genuine domain comprehension or pattern-matching against a known solution. If pattern-matching is detected, the ALE re-injects through a different symptom vector in the same technical domain. The credential proves the user can engineer in a domain, not that they recognize one of N canonical scenarios.

FIVE-STATE MACHINE · PAT-001 FIG 3
S1 · ObserveBaseline behavioral profile · idle ALE
S2 · DetectPattern-match signature in user output
S3 · First InjectStochastic failure · symptom vector A
S4 · AssessGenuine comprehension? · TTR + ET analyzed
S5 · Re-InjectSame domain · symptom vector B · pattern broken
↻ Loop until consensus reached or session ends
Strategy · why this is the moat against "training to the test"

Every existing assessment platform can be defeated by enough practice on the question bank — students memorize patterns, and the credential certifies pattern recognition, not competence. The Bully Logic Loop's second-order re-injection mathematically defeats this: a user who's memorized "503 → timeout fix" gets the 503, applies the timeout fix, and immediately sees a different symptom in the same domain (e.g., the auth key rotation). The pattern doesn't help; only domain understanding does. This is what makes the Proving Ground credential resistant to "training to the test" — the test rebuilds itself in response to the pattern.

PG v2 / F6Foundations · Command Authority & Proof of Friction (PAT-001)

The metric. The artifact.

PAT-001's two named outputs. Proof of Friction (PoF) is the forensic time-series record that justifies the CA score — every keystroke, every inference latency, every error correction, sealed. CA is what the Sovereign Passport displays as a headline; PoF is what the recruiter clicks to verify.

PG v2 / F7Foundations · The Council Inside the Gate (PAT-004)

Four agents. One Gate. Phase 2 active.

v2.0's most important architectural reconciliation: the Proving Ground is not run by a single "Bully AI." It is operated by PAT-004's four-agent council under Phase 2 (Active Assessment) of the Orchestrator's Session Phase Management. The Tenured Agent runs as Invigilator (user-facing, blue narration). The Chaos Agent dispatches via the ALE (gold [CHAOS] lines, environmental failures). The Auditor evaluates artifacts on the Blackboard (silent until Synthetic Review). The Mentor is suspended during a live Gate. This is the architectural truth the v1.0 spec missed.

v1.0 had a single "Bully AI" doing both the environmental injection and the gaslighting narration. v2.0 separates these per PAT-004's Conflict-of-Interest Architecture: the Chaos Agent writes [CHAOS] fiction in gold; the Invigilator writes [INVIGILATOR] facts in blue; real system errors stay red. PAT-004's structural insulation is what makes the eventual Consensus Certificate credible.
